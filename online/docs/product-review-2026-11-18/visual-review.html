增长黑客 / 增长酒馆：独立视觉评审

评审日期：2026-11-18（北京时间）。评审角色：视觉与交互设计。优先场景：课堂现场，第一次使用的同学迅速理解、加入并做出第一次决策。当前版本为线上版本 8；本轮仅评审，未修改产品代码或部署。

判断与证据边界

产品已经有可保留的审美资产：朱红折纸与纸白版面使学习区有编辑出版物的气质，暖暗酒馆、四席圆桌和实体人物使经营区有独立身份。上一轮酒馆按钮前置、56px 高、实心填色的调整有效，不能继续把“开始阅读更抢眼”当成当前问题。

目前最需要改变的是重要任务在画面中的位置和分量。把阅读区、酒馆区一律换成同一种背景，或再加一些光效、装饰卡片，不能解决首次开局的困难。应保留两种环境，并让每个阶段只出现一个明确的行动重心。

本评审查看了本次实际捕获的线上首页与酒馆入口、当前本地真实前端的阅读/实验/案例/札记，以及通过真实本地 API 完成六轮练习的桌面/手机宽度截图。手机是桌面 Chrome 的窄视口；3D 使用软件 WebGL，不能据此宣称实体手机性能或课堂投影可读性已经验证。练习使用三席脚本与模板主持，未实测公共多人局、付费模型。

证据入口：浏览器记录。文中“观察”指截图/实际 DOM；“代码”指当前样式定义；“判断”指设计师推断，需用户测试验证。

已经做对、建议保留的部分

  • 首页首要 CTA 已经与酒馆优先的目标一致；阅读按钮保持可见且权重较低。
  • 阅读区正文 18px、宽度约 700px、行高约 1.95，目录与正文分离，有良好的长文阅读基础。不要为了统一风格将正文缩成工作台的 13px。
  • 当前对局把经济数据放在右栏、行动放在独立面板，避免把表单和数字散落在 3D 场景上。这一结构方向应保留。
  • 提交状态、草稿、脚本席身份、模板主持、事实/传闻/核验区分、主持全文/往期、账本与导出已经存在。改进应提高它们的可见性，而不是重新实现一套重复功能。
  • 手机使用底部行动入口和独立编辑面板，主提交按钮宽度充足；原生表单控件和可见焦点也比自绘复杂控件稳妥。
  • 结束后已有分数、名次、写复盘、再开一桌和导出回放；问题在结果的视觉组织，不是缺少结果功能。

八项主要问题与具体改法

V1：首页的视觉承诺仍然偏“读一本书”，还没充分展示“马上经营一局”

等级：P2；证据：观察 + 判断。

线上首页的主图是沿折纸阶梯阅读的人，标题是“增长黑客”，作者与版次在主 CTA 下方。它很好地传达书的出处，但没有预览“我将看到什么、按什么、四个人如何参与”。同页下一段仍按“读一篇 / 做个实验 / 经营一局”排列。虽然按钮已经提升酒馆权重，其余视觉叙事仍主要服务阅读。

具体方案：保留折纸主图作为品牌资产，将右半区的一部分改成真实酒馆任务预览：显示一条教学情境、一个行动选择和“4 席 · 6 轮”的简短说明。首页标题下增加关系说明，例如“增长黑客课堂 · 用一局经营验证增长判断”。对于课堂邀请链接，可以直接进入加入房间，而不强迫用户经过营销首页。下方三条路径按课堂目标突出“先经营，再按问题补读”。

参考：Stripe Press 的书籍身份和编辑信息可以保留；酒馆预览采用自身真实界面，不复制其购书/探索导航。见下文 R3。

验收：让 5 名从未使用的同学看首页 5 秒，能说出“这是一个可直接开始的经营练习”及“阅读是辅助材料”；这是待验证目标，不是现有调研结论。

V2：夜间称呼输入框存在真实的样式失配，降低可读性

等级：P1；证据：线上观察 + CSS 可复核。

线上酒馆入口与手机入口中，“你的称呼”输入框是浅灰底，placeholder 同样偏灰，明显脱离周围深色控件。

public/style.css:37 的全局 input:not([type="range"]):not([type="checkbox"]):not([type="radio"]) 包含 3 个属性条件；public/tavern-v3.css:4 的 .night input:not([type=range]) 优先级较低，夜间背景 #151510 会被全局 #ffffff80 压过。这不是“深色主题不好”的审美争议，而是主题规则没有稳定生效。

本次浏览器 computed style 记录确认背景为 rgba(255,255,255,0.5)，文字为 rgb(238,233,221)，placeholder 为 rgb(133,135,127)，父背景为 rgb(29,28,23)，见 补充实测。按这些实际值合成，输入框背景约 #8e8e8b；placeholder 对它约 1.11:1，输入文字约 2.71:1。这是该控件的颜色组合计算，不是全站无障碍审计。普通文本与 placeholder 的可读性目标应按 4.5:1 检查。W3C 对比度说明

具体方案：让输入背景、文字、placeholder、边框全部使用语义 token，并将共享基础选择器置于更低优先级（例如 :where()）或明确统一主题层级；不要继续追加零散的 !important。日间与夜间分别检查输入、textarea、select、自动填充、焦点和错误状态。

验收：当前称呼框的暗色背景在桌面/手机实际生效；placeholder 和输入文本分别达标；焦点与错误边界可识别；不让札记标题输入框等日间表单被一起改坏。

V3：手机首次入口的介绍面积过大，真正的“入席”低于首屏

等级：P1；证据：观察；影响为待验证判断。

390px 手机入口中，导航、标题、介绍、席位/回合说明、主持披露和延伸链接先出现，表单从约 554px 才开始。“入席”按钮的浏览器实测位置为 top 906.94px、bottom 951.44px，见 补充实测；844px 高度的初始视口看不到主按钮。已有页面没有横向溢出，但这不能证明首次开局顺畅。

具体方案：针对课堂入口，压缩上半区为标题、两行任务说明、模式信息，优先显示“加入课堂房间”或“先练习一局”的入口。游戏规则、Agent 授权、模型披露放在相关控件后的可展开说明，默认展开与用户当下任务直接相关的信息。“新开一桌 / 加入房间”仍保留，不凭视觉评审直接改变模式默认值；邀请链接优先呈现房间与昵称表单。

参考：借鉴 Lichess 页面把核心参与面放到主要视野的空间组织；不复制棋类专业参数。见 R4。

验收：390×844 下，不滚动即可发现当前模式的主要入口；输入键盘出现后仍能找到提交按钮；在实际 iOS Safari 与 Android Chrome 复核键盘、安全区和缩放，不能只验桌面窄视口。

V4：3D 具有识别度，但决策阶段仍占据过多的有效注意力

等级：P1；证据：观察 + CSS；方案比例是设计起点。

手机首轮决策中，3D 场景约 404px 高；顶部状态与经营数据后，场景一直延伸到约 564px，接着是主持、情报摘要和底部行动入口。tavern-v3.css:20 的手机场景高度限定在 370–410px。玩家进入决策期后，视觉中心还是房间、桌椅与人物，真正用于判断的证据和行动依赖二次展开。

这不意味着需要删掉 3D。圆桌与四个人是产品区别于普通练习页的资产；问题在于同一张布局没有随着任务阶段切换重心。

具体方案：候场阶段保留完整圆桌；决策期将手机场景原型起点设为约 200–240px，并可展开查看四席，主面板显示“本轮要做的决定 → 关键证据 → 行动”。桌面原型起点可为场景约 300–340px，保留独立右栏。提交后再突出已接收状态与其他席位进展。结束后缩为席位横栏或小型纪念视图。所有数值均需结合内容与实际设备验证，而不是直接写死为最终规格。

参考：Linear 的支持性界面退后、任务内容靠前原则；Lichess 的稳定主参与面。借鉴优先级，不照搬暗色、图标密度或棋盘大小。见 R1/R4。

验收：首轮用户无需滚动即可看见当前目标、关键证据入口和行动入口；长昵称、系统字体放大、横屏和 320px 宽度下不遮挡状态；不把软件 WebGL 的截图流畅度当真实性能验收。

V5：关键说明和辅助说明的字号、色阶接近，扫读时难以区分“必须知道”

等级：P1；证据：观察 + CSS；并非判定所有暖灰文字不达标。

桌面首轮的未提交状态、字段标签、成本解释、主持标识、情报分类等大多使用 13–14px 与接近的暖灰/金褐色。tavern-v3.css:12、:15、:61–66 可以看到这种密度。事实、传闻、核验已有文字分类，是良好基础；但在 45 秒决策中，长说明与次要元数据仍可能获得近似的视觉权重。

具体方案：将层级限为四级：当前任务/主数值；本轮关键事实/已选行动；操作标签/解释；来源/时间/辅助信息。任务与说明正文使用 16px，标签 14px，13px 留给时间、来源和非关键元数据。事实、传闻、核验使用明确文字标签和不同形态，不只换颜色；损益使用正负号与说明。边框仅用于区分不同任务容器，同容器内靠间距分组，避免每段文字都加一条线。

参考：Linear 2026 官方改版对侧栏、分割线和图标的处理；借鉴“按职责降低视觉竞争”，不能把关键证据也一并调暗。见 R1。

验收：5 秒扫读能辨认本轮、状态、可用预算与一条关键证据；重要说明在实体手机与课堂投影环境可读；对比度按实际前景/背景逐项测量，不用“看起来高级”代替检查。

V6：指标的大小在暗示“现金最重要”，但结果讨论需要平衡多项指标

等级：P2；证据：观察 + CSS；用户理解风险为判断。

右栏现金是 29px，综合分与有效用户是 19px（tavern-v3.css:15）。结束桌面截图仍然是现金最大，综合分在侧栏次级位置；中央结束摘要虽有分数与名次，但没有紧邻的一组变化证据。用户可能把“保留更多钱”当成隐含目标。

具体方案：决策期把现金明确标为“当前可用资源”，并将投入和预留运营费与预算组成一组；综合分、有效用户用于理解整体经营，提供同级但不同用途的标签。结束期综合分/名次上移，同时并列呈现有效用户、净利润等结果及变化，不把“优化分数”变成唯一学习目标。用 font-variant-numeric: tabular-nums 保留数字稳定性，不依赖更多小数表现精确感。

验收：受测同学能说清现金、用户、综合分分别在回答什么问题；不用阅读隐藏说明才知道现金不是唯一胜负目标；结果仍明确区分相关变化和行动因果。

V7：主持信息有出处与全文，但“两行摘要 → 长弹窗”的颗粒度跨度太大

等级：P1；证据：观察 + CSS；不是要求模型给出最优行动。

桌面主持条只显示两行，手机同样截断；全文弹窗可读性尚可，并有往期和引用知识。但初次使用者从一段长句的截断版本跳到完整长段落，仍需自行提取当下最相关的信息。

具体方案：保留原文、模板标识、知识来源与往期；摘要改成可扫读的三项：已确认事实、尚未核实的信息、需要权衡的问题。摘要可以由确定性字段组织，不要求模型推断赢家或输出最优策略。主面板只展现当轮最相关的一条证据，展开后可看原句、轮次与来源；不要在事实已经展示后再重复一遍无差别长文。

参考：Readwise Reader 的原文与标注/笔记并存、阅读时可收起侧面板的方法。迁移的是“证据与解释保持关联”，不是把工作台改成全文阅读器。见 R2。

验收：同学能在 10 秒内区分一条事实和一条未核实信息；展开后能找到原文；摘要不能改变原意或把传闻升级为事实；主持状态和失败/模板回退标识仍可见。

V8：结束阶段没有充分把画面从“在局中”切换成“理解结果”

等级：P1；证据：观察 + CSS。

桌面结束仍让原来的完整圆桌占据主画面；手机结束在圆桌下保留主持，底部固定结果面板覆盖了部分主持内容。“六轮经营告一段落”和“写下这局复盘”已经存在，但结束页的视觉主轴仍像决策中。

具体方案：结束期切换为文档流式复盘页面：结果摘要 → 关键转折轮次 → 你当时的行动/证据 → 可写的三段复盘 → 再试一次/导出。保留小型桌面或四席头像体现共同经历；不要要求用户在固定底部摘要、主持条与右栏账本之间自行拼出整局。将现有账本与回放作为证据入口整合，而非再造数据源。复盘输入旁放相关回合变化，减少记忆负担。

参考：Lichess 分析棋盘中参与面与记录/复盘控制的并置关系，以及 Readwise 的原文与注释关联。只迁移复盘组织，不把随机教学经营结果包装成象棋引擎式的确定性“最佳走法”。见 R2/R4。

验收：手机完整结果不会遮住主持或正文；用户能定位一个关键回合并带着证据填写复盘；出局后仍可查看全部数据、重开或导出；普通滚动和键盘操作均成立。

下列内容于 2026-11-18 查证，优先使用官方公开资料；营销图不等于登录后实际完整体验。每条“迁移”都是针对本产品的设计推导。

R1 · Linear：工作区层级与颜色职责

官方来源：A calmer interface for a product in motion（2026-03-12），另见 2024 UI 重设计方法。

已观察：2026 文章展示侧栏、图标、分割线前后对比；支持导航的信息退后，当前任务内容更突出。2024 文章讲到跨环境、颜色变量和结构层级的验证。已肉眼查看 官方侧栏对比图 与 官方边框对比图；这是官方设计示意，未登录 Linear 工作区。

迁移：用于酒馆的 HUD / 行动 / 情报三级布局；将状态、字段、解释、来源分出大小与色阶；减少同级盒子与分割线。颜色按“背景/表面/正文/操作/状态”管理。

不照搬：开发者工作区的小字号、隐藏式快捷键、密集图标、冷灰品牌以及复杂导航。课堂新手需要更大的说明与显式步骤。

R2 · Readwise Reader：让解释始终和原证据相邻

官方来源：Reader 产品页、侧面板与导航说明、标注与笔记说明。

已观察：官网提供原文标注、文档笔记和资料列表的公开 UI 图；官方文档说明可设置阅读时侧面板默认可见性。已肉眼查看 原文标注示意 和 资料与笔记并置示意。图片为公开营销素材，部分素材可能来自更早版本，不据此认定当前登录后像素布局。

迁移：用于主持全文/来源和复盘：点击一条变化，旁边出现对应回合原始事实；写复盘时保留选中证据。长文阅读默认主文优先，辅助解释按需出现。

不照搬：多库、多标签、多来源导入与订阅组织。本项目只有六主题和一局经营，不需要增加复杂的信息管理负担。

R3 · Stripe Press：编辑身份与真实内容资产

官方来源：Stripe Press。

已观察：本次官网截图可见黑色环境中的实体书体、巨幅书名、克制的书目/多媒体元数据，真实内容资产承担主要识别。长截图有未完整触发的滚动内容与留白，不能据此评价所有动态行为；没有把这一张长截图当作完整动效测试。也不将其当前官网误称为纸白页面。

迁移：保留本项目的纸白/朱红/作者出处，统一图片比例和版式节奏；把折纸插画用于品牌与知识板块，把真实经营界面用于说明实际产品。
