# 增长黑客 · 增长酒馆产品详评与改进方案

2026-11-18 · 当前线上版本 8 · 评审主场景：课堂现场与首次开局

## 01 评审结论与推荐方向

这个产品已经有可辨认的气质：纸白、朱红、折纸插画的阅读环境，以及暖暗色、真实围桌、球形市场的酒馆环境。阅读、实验、经营和札记也都有实际功能。最值得投入的下一步，是让第一次来的同学能顺利加入同一桌、理解自己经营什么、做出一个有依据的决定，并在结束时解释一次结果。

**推荐采用「有引导的增长酒馆」：酒馆承担课堂主线，阅读、实验和札记围绕具体决策提供帮助。** 保留双环境和真实圆桌，把视觉资源按等待、决策、结算、结束四个阶段重新分配。先做入口与第一轮，再做复盘闭环，最后精修展示与实验内容。

上一轮已经完成的主按钮调整有效：首页「进入增长酒馆」在前、朱红实心且更大；本次不再把它当待办。当前瓶颈已进入入口之后的任务组织与学习支持。

| 设计路线 | 优点 | 对课堂首次开局的代价 | 本轮取舍 |
| --- | --- | --- | --- |
| A 编辑式互动教材 | 阅读舒服，知识结构稳，品牌延续自然 | 酒馆容易继续成为教材里的一个附属入口 | 保留其内容与排版作为支持层 |
| B 有引导的增长酒馆 | 共同在场、目标清楚、决策与学习相接 | 需要梳理入口、状态和信息优先级 | **推荐主方向** |
| C 强沉浸经营游戏 | 演示吸引力与空间氛围强 | 容易继续挤压手机上的情报、动作和复盘；制作成本也高 | 暂缓整站游戏化扩张 |

建议用一句话对外说明：「和同学经营自己的公司，在同一个市场里做六轮决策，复盘增长判断。」四席各自经营，不能宣传为四人共同经营同一家公司。Agent 可作为可选搭档，用户应明确知道可以全程手动操作。

## 03 已经值得保留的资产

- **首页与阅读的编辑感。** 纸白背景、克制红色、清楚的长文层级和留白，已比通用管理后台更有识别度。当前章节有目录、阅读设置、学习提示与出处边界。
- **酒馆真实在场感。** 四席、身份头像、暖木材质、真实球体具有记忆点。目标是调整它在不同阶段的占比，而不是用平面装饰替代。
- **动作的真实反馈。** 草稿、提交中、接收、失败、不确定、截止锁定已有区分；已提交不等于立即结算，也不是自动替用户做决定。新设计必须继续忠实表现这些状态。
- **诚实的教学边界。** 三席脚本、模板/模型主持、事实/传闻/核验、教学案例与模型的边界均有说明。不能为了简洁把影响判断的说明删掉。
- **可用的学习积木。** 三个变量实验、选择式案例、六个阅读主题、回合账本、知识引用和结果写札记已经存在；先串起来，避免重复造功能。
- **邀请与恢复基础。** 带房间参数的邀请会自动切到加入，已有有效会话可回原席位。这比每次重新选模式更接近课堂需要。

## 04 五维设计初评

以下为评审者按当前证据给出的启发式判断，满分 10，等权平均 **6.6**；不是用户满意度、转化率，也不是与外部产品的客观排名。

| 维度 | 初评 | 证据与判断 |
| --- | --- | --- |
| 哲学一致性 | 7 | 阅读与酒馆各自有气质；进入酒馆前对实际经营的预期衔接仍弱 |
| 视觉层级 | 6 | 主 CTA 已改善；手机决策和结束时场景仍占首屏主要面积 |
| 细节执行 | 6 | 排版与状态较完整；暗色称呼框样式失配、主持截断等问题可直接观察 |
| 功能服务目标 | 6 | 六轮可走通，但首次课堂路径和从结果到证据的学习路径仍需组织 |
| 独特性 | 8 | 「书—实验—酒馆—札记」与真实围桌有独特组合，值得继续发展 |

首要提升应落在功能服务目标和视觉层级。单纯增添动效、插画或新色板，对这两项帮助有限。

## 05 逐项问题与具体改法

优先级定义：P0 为课堂首次正确入席与第一轮决策；P1 为理解、反馈、可靠写作和复盘；P2 为体验顺畅后再扩展的内容与精修。它们是实施顺序，不代表所有用户都已经失败。

### F01 / P0 入口需要先识别课堂角色

**观察。** 当前酒馆默认「新开一桌」，游戏模式默认四人同桌，另有「加入房间」页签与下拉中的单人练习。主按钮统一叫「入席」。已有邀请链接自动切加入，这部分是优点。证据：[线上入口](screenshots/live-entry-desktop.png)、app.js 的 tavernLanding / prepareInvitationEntry。

**影响判断。** 被要求加入组长房间的同学可能先创建自己的桌；这是合理风险，尚无真实误建率。

**具体方案。** 有邀请时只呈现目标桌、称呼与「加入这桌」；同设备已有席位则先显示「回到原席位」。无邀请的课堂入口，主任务是「输入房间代码加入」，另有「自己先练习」和「我是组长，开新桌」。建桌者看到邀请与人数状态，普通同学看到自己在第几席、等谁开局。无需增加账户注册或新的课堂组织后台。

**验收。** 邀请直达仍只需称呼；错码、满员、已开局、网络待确认均有对应恢复动作；四名新人能进同一桌并说出谁负责开始。参考 Lichess 的意图分流与 BGA 当前行动条。

### F02 / P0 手机入口的行动应在首屏可达

**实测。** 390×844 视口下，「入席」按钮顶部 y=906.94、底部 y=951.44，初始不可见。不是按钮尺寸太小，而是导航、介绍、主持说明和表单依次占用了高度。证据：[手机入口](screenshots/mobile-tavern.png)、details-evidence.json 的 entryMetrics。

**具体方案。** 邀请页优先呈现房间与称呼；普通课堂页先呈现加入表单。保留「4 席 / 6 轮 / 每轮 45 秒」短说明，将长介绍与 Agent 消耗说明放到相关入口旁的解释区。普通玩家的首屏目标是理解并加入，不能要求先读完产品介绍。

**验收。** 在 360×800 与 390×844、100% 缩放中，称呼/代码与主加入动作可见或一次自然滚动可达；软键盘打开后不遮住当前输入与提交。后者必须在实体手机验证。

### F03 / P0 开局前要说明经营对象、价值与获胜条件

**观察。** 桌面顶栏显示「AI 笔记工具」，但首屏主要是现金、综合分和有效用户。手机练习顶栏隐藏了产品名；API 已提供的 coreBehavior / northStar 没有在当前对局界面完整说明。证据：[桌面第一轮](screenshots/desktop-first-decision.png)、[手机第一轮](screenshots/mobile-first-decision.png)、产品评审 UX-02。

**具体方案。** 在等待区增加一个可收起的「本局任务」：经营什么产品、什么行为算用户获得价值、综合分按哪些已存在规则组成、六轮后如何比较。使用当前抽到的产品数据，不硬编码 AI 笔记。正式开始后保留产品名与一个概念入口；详细规则按需展开。

**验收。** 新人开始前能用自己的话说明经营对象和有效用户；能找到分数说明。多人局仍由房主统一开始，不为每个人新增阻塞式同意步骤，也不擅自延长真实规则的倒计时。

### F04 / P0 十二行动需要比较依据，避免默认值像推荐

**观察。** 行动表单以三个 select 表示行动、人群、投入；默认草稿为付费获客，但已有「本轮尚未提交」，并没有自动投放。预算和当前行动机制会更新，十二项的横向比较仍需逐个浏览。证据：第一轮截图、app.js 的 currentDraft / decisionMarkup。

**具体方案。** 保留全部行动与成本，按目的呈现「拉新 / 激活 / 留存 / 收益 / 研究」等分组；每项提供一句作用、适用问题与主要代价。首轮显示「先判断问题，再选行动」的可关闭提示；在等待或单独样例中演示一次费用与确认。分组为草案，实施前逐项核对 engine ACTIONS，不能按名字猜公式。

**状态要求。** 草稿显式标「默认草稿，可修改」，未点确认不会生效；不把默认 A01 描述成系统建议。熟悉者仍可跳过帮助、快速选择；正式 45 秒内不弹强制教程，不提前泄露未来事件或他人私人决策。

**验收。** 新人无需逐项试完就能找到两种处理不同问题的行动，知道费用是预算估计而非保证收益，确认后能辨认接收状态。

### F05 / P0 手机决策优先展示证据与动作，场景按阶段伸缩

**实测观察。** 390×844 的第一轮，场景约 405px 高，接近视口 48%；下方还有主持、情报预览和固定行动栏。进入行动底部面板后，选择、费用与确认清楚，但本轮情报与选择理由不能同时扫读。没有观察到横向溢出；这是任务面积分配问题。证据：[第一轮](screenshots/mobile-first-decision.png)、[行动面板](screenshots/mobile-action-sheet.png)。

**具体方案。** 等待时可大幅展示围桌；决策时默认将场景收至约 220–260px，并保留「展开圆桌」。其下直接呈现已确认变化，以及如有的尚未核实消息、预算与行动入口。行动面板内带一个可展开的本轮情报摘要，关闭后保留草稿和原位置。结束时场景折叠为身份背景。

**验收。** 360–430px 宽度下，用户不用操作 3D 就能读证据、选行动、看预算并提交；不会同时出现两个主要确认按钮；安全区、键盘、焦点返回和后台回前台需在真机测。220–260px 是待验证的起始参数，不是已证明最优高度。

### F06 / P1 暗色称呼输入框发生样式覆盖与低对比

**实测。** 称呼框计算背景为 rgba(255,255,255,0.5)，父容器是 rgb(29,28,23)，输入文字为 rgb(238,233,221)，placeholder 为 rgb(133,135,127)。基础 CSS 带三个 :not 的输入选择器压过了酒馆夜间选择器，导致浅灰底。按合成估算，placeholder 对背景约 1.11:1，输入文字约 2.71:1。证据：details-evidence.json、style.css:36–41、tavern-v3.css:4。

**具体方案。** 为真实表单控件建立统一、明确作用域的深色样式，修正选择器关系；placeholder 只作辅助，保留可见标签。核查同类输入的 normal / focus / error / autofill 状态，避免只改一张截图。

**验收。** 普通文字和 placeholder 达 4.5:1 的目标；焦点与错误可辨。此为具体字段问题，不据此宣称全站不合规。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

### F07 / P1 主持与情报要先便于扫读，再提供全文

**观察。** 当前主持常驻、可展开全文、可查看历史和知识来源；这是重要资产。正式轮次常驻正文只有两行，长机制/公式可能被截断；情报栏中事实、传闻、核验和解释的字号/暖色层级相近。证据：[主持详情](screenshots/desktop-host-detail.png)、第一轮截图。

**具体方案。** 常驻摘要按「确认变化 / 尚未核实 / 值得思考」组织，最多两三条短句；各自带文字标签。全文和引用继续按需展开，来源状态继续诚实区分。规则模板也能生成这些摘要，不把改界面前置为新增模型费用。不能把传闻写成事实，或把建议做成保证胜负的指令。

**验收。** 学生在倒计时内能指出一条事实、一条传闻；展开/关闭后选择和草稿保留；每条结论仍能回到其公开来源。参考 BGA 日志和 NN/g 渐进披露。

### F08 / P1 结算应帮助解释「这轮发生了什么」

**观察。** 回合历史与账本已存在，主持会给实际行动、分数变化等信息；这些散在不同区域。当前页面需要玩家自己把行动、多人竞争、事件与结果联系起来。

**具体方案。** 利用已有账本形成一条结构化结算摘要：「你做了什么 → 现金/有效用户/分数如何变 → 本轮已知外部变化 → 查看明细」。结果数值来自真实结算；没有明确分解的因素只列为可能解释，不伪造确定归因。正式局自动推进规则不变，不新增需要四人逐个点下一步的阻塞。

**验收。** 任一摘要能跳回对应轮次和数据；上升不直接等同正确决策，下降不直接判失败；不同人群与对手共同作用不会被省略成单一因果。

### F09 / P1 结束页应把真实结果与可复盘回合带到前面

**观察。** 六轮结束已有分数、名次、有效用户、累计利润，以及「写下这局复盘 / 再开一桌 / 导出回放」。结果内容不是缺失。问题是大场景仍占主体，右侧默认还是情报；手机固定结果区还覆盖部分主持区域。证据：[桌面结束](screenshots/desktop-finished.png)、[手机结束](screenshots/mobile-finished.png)。

**具体方案。** 结束后默认切「结果与复盘」，大场景收起；依次展示最终结果、能核对的得分构成、六轮轨迹、一处可自行选择的复盘回合，再写「事实 / 我的解释 / 下次验证」。优先按时间和指标变化筛选，不默认将某轮负值判成错误。保留原始完整账本和回放导出。

**验收。** 用户不下载 JSON 也能定位一轮实际行动及结果；札记附真实房间/轮次/来源；不得给未运行的反事实展示确定结果。参考 Lichess 定位决策与 BGA Endgame。

### F10 / P1 Agent 的价值应可见，可选性也应清楚

**观察。** 入口主文案是「和自己的 Agent 入席」，表单已把偏好与授权折叠；小字说明支持手动，房内有连接入口。第一次来的学生仍可能误以为先准备模型或客户端才能玩。

**具体方案。** 在加入动作附近说明「可以全程手动，Agent 可选」。先让用户知道它能提供什么帮助，再在需要时展开连接步骤；连接状态区分未连接、已复制待自检、已连接；授权模式另列建议与自主，分别有明确文字。高级授权继续在用户主动打开后展示，不更改已有权限边界或费用承诺。

**验收。** 新同学知道不连接也能完成一局；已接入者知道建议与自主提交的区别；不得把三席脚本包装成真实智能体或真人。

### F11 / P1 学习帮助应回到原决策上下文

**观察。** 阅读末尾、实验与案例都有到酒馆或札记的路径；游戏知识引用也存在。它们更多是页面跳转，阅读、变量实验与具体轮次仍缺少一致的返回结构。

**具体方案。** 决策中先给两句原位概念解释，长文和实验放在结束后深入。复盘里的概念卡能打开相关段落并回到刚才轮次；札记保留房间、轮次、知识主题与用户自己的解释。不要在 45 秒中强行把人带去九分钟章节。参考 Reader 的旁注与返回来源。

**验收。** 关闭概念卡不丢草稿；读完可回原位置；任何局后链接都指向真实来源，不只回到首页。

### F12 / P1 未保存札记的路由切换会丢失正文

**本轮复现。** 在札记输入「课堂评审草稿：暂不保存」，切到阅读地图，再回札记，textarea 为空。现有明确保存、本机说明与导出都存在；它们保护已保存笔记，不能覆盖编辑中草稿。证据：details-evidence.json 的 noteDraftBefore / noteDraftAfter / noteDraftLost。

**具体方案。** 将编辑草稿和正式札记分开保存；本机自动暂存，回页提示「已恢复草稿」，保留正式保存动作与本机范围说明。保存失败要有就地恢复方法；涉及跨设备同步另立项目，不在此阶段引入账户系统。

**验收。** 新建/编辑笔记在切页、刷新后能恢复未提交正文；清空或丢弃草稿是明确行为；本机存储不可用时仍能导出/复制当前正文。

### F13 / P2 首页继续把「书」与真实经营体验接起来

**观察。** 主按钮已突出，但标题、折纸图、作者出版信息和下面路径仍以阅读为先。对只看到首页的新同学，接下来是一个可立即加入的经营桌，还是必须先读教材，预期仍可能模糊。

**具体方案。** 保留「增长黑客」品牌与折纸插画，在主入口附近补「课堂可直接加入 / 4 席各自经营 / 6 轮」及一张真实经营局部预览；下面路径按「先经营 → 回看为什么 → 做个单变量实验」组织为建议路径，同时保留自由阅读。作者信息移到支持层，内容不删除。

**验收。** 新同学五秒浏览后能说出下一步是进酒馆、加入或练习；不把五秒当已测指标。参考 Stripe Press 的编辑身份与 Duolingo 的明确下一步，不照搬大面积书籍 3D 旋转首页。

### F14 / P2 实验从「有变化」走向「能比较自己的判断」

**观察。** 三个教学模型已经可操作、即时反馈，且写明不是实际经营预测。仍主要是拖滑块与读结果。

**具体方案。** 每个实验增加一个可跳过的预测、固定基线和一次对照，显示「原先判断 / 模型结果 / 解释」。例如保持新增不变，比较两种留存；默认只变一个因素，再允许自由探索。将问题关联到局后的真实疑问，避免把实验放在加入前设为必修。

**验收。** 学生能解释变量变化的方向与模型假设；结果不被包装为本局收益承诺。参考 Brilliant 当前官方描述的问题、操作与即时反馈机制，未使用旧版关卡截图作证。

## 07 推荐的信息结构与视觉尺度

### 课堂主线

首页 → 进入增长酒馆 → 按邀请/代码/组长/练习分流 → 本局任务与等候 → 第一轮行内提示 → 决策与真实回执 → 每轮结算摘要 → 结果与逐轮复盘 → 相关概念/实验 → 保存札记。

阅读地图继续作为自由入口，课堂主线不会要求先读完。真正的课堂同桌与独自练习是两条路径，不能默认让全班各建一桌。

### 屏幕构图

**桌面决策：** 顶部固定位置呈现产品/当前轮次/倒计时；主要内容区由情报与行动组织，圆桌仍可见但不把行动推到折叠区。预算、行动成本和确认保持邻近；历史、规则与 Agent 连接为次层。具体左右分配在原型中比较，不能仅因别的网站把操作放右侧就照搬。

**手机决策：** 状态与本局对象 → 关键指标 → 紧凑圆桌 → 本轮证据摘要 → 单一行动入口。行动面板带预算与情报引用，主确认固定于面板底；不在背景再重复可点击的确认。等待时允许展开大场景，结束时先结果与轮次。

**结束：** 最终成绩和得分解释 → 六轮轨迹 → 选择一轮回看 → 事实/解释/下次假设 → 保存复盘。完整围桌可再展开，身份与参与感继续保留。

### 视觉 token 起点（建议，实施时需测对比度）

| 类别 | 建议 | 理由 |
| --- | --- | --- |
| 阅读环境 | 继续 #f7f5f0 纸白、#242522 墨色、#c83732 朱红 | 延续已建立的编辑身份 |
| 酒馆环境 | 暖暗底 #151510，层级面 #1d1c17 / #25241d，主文字 #eee9dd | 以少量表面层级区分任务，不靠更多边框和光晕 |
| 强调 | 沿用现有暖橙动作色；朱红与暖橙属于同一品牌的两环境映射 | 不强迫把阅读红直接用于深色小字；每一环境主动作语义一致 |
| 语义 | 事实、传闻、核验、接收、失败都带文字标签 | 不只用座位颜色或红绿传达状态 |
| 正文字号 | 手机决策关键正文 15–16px，辅助 13–14px；阅读保持 17–18px | 关键情报不与脚注挤在同一级 |
| 标题/数字 | 页面标题 32–40px；模块 18–22px；关键指标 24–30px，数字等宽 | 中文层级靠字号、字重和位置共同完成 |
| 控件 | 关键触控目标建议至少 44px，主操作 48–52px；现有首页主 CTA 56px 保留 | 这是设计目标；WCAG 2.2 AA 最小目标要求是 24px 或符合例外，不能混称为 AA 44px |
| 空间 | 常用 4/8/12/16/24/32；控件 8–12px 圆角，面板 12–18px | 统一比例，避免所有内容都变成大圆角卡片 |
| 动效 | 约 160–240ms，主要用于面板与状态切换；遵守减少动态偏好 | 45 秒决策不需要自动播放的装饰竞争 |

指标大小按阶段调整：决策时现金/可用预算是行动约束，可以突出；结束时综合分及其解释成为主轴。不简单地把全程最大数字改成综合分。控件建议依据与例外见 [W3C 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

## 08 不同子智能体意见如何取舍

| 讨论点 | 不同视角 | 总控决定 |
| --- | --- | --- |
| 先练习还是先入课堂 | 教学参考强调先让人做一手；课堂产品评审担心每人误建练习 | 邀请和课堂代码优先；练习为明确可选路径，等待时给样例 |
| 现金还是综合分更突出 | 视觉评审发现现金最大而最终比较综合分；产品操作需要预算依据 | 随阶段分配：决策突出预算，结局突出综合分与构成 |
| 3D 是否应该删除 | 手机截图显示占屏过多；视觉与产品都认可围桌的品牌资产 | 保留真实场景，按阶段收放，先让手机操作与证据可见 |
| 主持要不要简化 | 可读性要求短；可信解释需要全文与来源 | 常驻短摘要，完整正文/来源仍可达，不能删事实边界 |
| 学习路径是否锁成关卡 | 参考路径可减少选择；现有阅读强调自由探索 | 提供一个建议下一步，同时允许跳过与自由阅读 |

## 09 可执行计划与依赖

工作量为任务规模估计：S 通常半日至一日，M 约一至两日，L 约二至四日，均需结合实现后复验；不是交付承诺。可复用现有接口时按较小规模估，涉及数据契约则先补规格。

| 批次 / 任务 | 范围与具体交付 | 规模 | 依赖 | 通过条件 |
| --- | --- | --- | --- | --- |
| A1 课堂入口 / F01–02 | 邀请/代码/组长/练习四种上下文；角色清楚的按钮与错误恢复；手机首屏重排 | M | 先确认主路径文案 | 新同学入正确桌；保留原席位恢复；不误建桌 |
| A2 开局任务 / F03、F10 | 从 state.product 渲染价值/核心行为，从 state.rules 渲染分数说明；明确 Agent 可选 | S–M | A1 场景一致 | 新人能说明经营对象、目标和手动可用 |
| A3 第一轮 / F04–05 | 行动分组与解释、默认草稿语义、等待样例、手机紧凑场景与上下文 | L | A2；逐项核对 ACTIONS | 首轮合法提交；不改规则/倒计时/权限；草稿不丢 |

**建议先实施 A 批并做课堂试验，再投入 B 的复盘闭环。** C 中的首页文案等小项可顺带完成，但不能因为容易截图好看而挤掉首局关键工作。无需先新增匹配大厅、排行榜、成就、账号、更多模型或新经营规则。

若只做三个快速改动，先修暗色输入框、在加入动作旁说明手动可玩/Agent 可选、明确邀请页「加入这桌」的动作语义。它们是小成本收益候选，不能替代 A 批完整路径。

## 10 验证方案：用任务成功评估改动

建议先用当前版记录基线，再用可点原型做一次迭代，随后在真实受控四人桌复查。8 名从未使用过的同学可分成两桌，覆盖组长、邀请、代码、普通手机。这个规模适合发现卡点，不足以宣称统计显著的转化提升；交换版本需要记录学习效应。

| 任务 | 记录什么 | 建议的第一轮验收目标（尚未达到、需要实测） |
| --- | --- | --- |
| 加入指定桌 | 从看到邀请/代码到成功入席的耗时、误建桌、求助点 | 8 人中至少 7 人无需口头帮助入正确桌，0 次因分流误建桌；耗时先测基线再定 |
| 理解本局 | 复述经营对象、有效用户、如何比较结果 | 至少 7 人能准确复述对象与核心行为 |
| 第一轮选择并提交 | 合法提交耗时、看过什么证据、是否误解默认行动 | 至少 7 人在规则时限内合法提交；不能只以确认按钮点击量算成功 |
| 判断状态 | 复述草稿/已接收/已锁定/失败/不确定 | 至少 7 人能分清接收与锁定；弱网不确定不误报成功 |
| 结束后复盘 | 找到真实轮次、说出事实与解释、提出下次假设 | 至少 6 人能给包含真实回合证据的解释；不以胜负判学习成功 |
| 暂存与恢复 | 札记切页/刷新、房间刷新回席、面板返回 | 原内容/草稿/身份可恢复；错误时有下一步 |

另在受控环境测错码、满员、过期、临时离线、提交响应丢失、手机键盘和安全区、减少动态偏好、只用键盘。多人权限、未来信息隔离、经济规则、来源诚实和回执语义是改版必须守住的回归范围。自动化截图或脚本走通不能替代真实新同学的理解测试。

[NN/g 渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)支持按任务推迟高级选项，但关键选项不能藏得难找；[状态可见性](https://www.nngroup.com/articles/visibility-system-status/)支持持续清楚地告知当前状态。这里的改法仍需由本产品的真实课堂任务验证。

## 11 本轮交付与下一步边界

本轮完成的是多视角详评、当前版本证据、官方参考映射、推荐方向和分批改进规格。附带的界面结构示意用于讨论改进，不连接房间、不代表生产实现，也不编造实测效果。

实施的第一步应从 A1–A4 开始：把「加入正确的一桌 → 读懂本局 → 有依据地提交第一轮」做成完整可验收路径。上线产品仍为版本 8，评审没有直接改动或发布它。
