增长黑客 / 增长酒馆：产品体验参考调查

调查日期：2026-11-18（北京时间）。调查者：独立参考研究子智能体。

本轮目标是课堂现场第一次使用：同学应很快知道自己要加入哪桌、现在轮到做什么，以及一局之后学到了什么。酒馆为主入口，阅读、实验和札记为理解与复盘的支持。以下是设计建议，未修改产品、创建外部账号、参与线上对局或调用付费模型。

证据范围

此次实际打开并阅读了五组产品的官方页面、官方文章及官方文档。对于可抓取的公开页面，能核实内容和入口名称；没有把抓取的文字当成完整视觉截图，也没有将官方介绍当成登录后操作实测。BGA 主站 FAQ 首次访问仅返回加载壳，另一次教程页超时，因此 BGA 的依据主要是其官方 UX PDF、官方教程公告和官方文档索引。Duolingo 首页没有返回可审查的产品界面，依据是官方带界面图注的文章。Brilliant 课程内、Reader 登录后、Lichess 实际对局与分析均未实际操作。

本地映射基于 growth-atlas-v3/public/app.js 的当前代码：酒馆入口 L79、邀请自动加入 L80–85、等待入席 L151、行动表单 L154–155、结束与保存复盘 L153/L254。已存在的功能不应重新当作“缺失”立项：邀请链接能自动切到加入、Agent 偏好已收起、练习明确标注脚本席、房间可恢复、结果能写入札记。

五个参考，分别借鉴什么

1. Lichess：按来访意图分入口，结束后回到具体决策

官方证据。 当前公开首页直接提供建立对局、挑战朋友、对电脑三个按钮，也单独列出学习和分析入口。官方介绍说明结束后可以请求电脑分析；2026-06-06 更新的官方盲人模式教程，第 5.5 节说明复盘会定位具体失误，隐藏现成评价，让玩家重新尝试，并提供看答案、跳过。前者是当前公开网页；后者是官方功能说明，未在账户内实测。

用于我们。 酒馆大厅不再把“我要加入别人”和“我要组织一桌”混成一个通用“入席”。保留已有邀请上下文：带 room 的链接只显示该桌信息与称呼，主按钮写“加入这桌”；没有邀请的课堂入口优先“输入课堂代码加入”，旁边明确“自己先练一轮”，另设“我是组长，开新桌”。这里借的是入口按意图显性分流，不是抄 Lichess 首页的信息密度。

结果页结构。 “最终表现 → 本局一处值得复盘的决策 → 当时公开信息与行动 → 再说一次你的判断 → 对应概念阅读”。文案可以是“回看第 3 轮：你为何选择加大投放？”而非仅展示成绩和下载 JSON。已有“写进我的札记”继续保留，补上到具体回合的入口。

边界。 国际象棋有明确的引擎评价；增长酒馆存在多人选择与事件共同作用。不能把负增长直接判成用户“犯错”，不能给未运行的反事实下确定结论，也不应在未有能力时承诺“最佳行动”。建议用“值得复盘”代替“错误”。未验证 Lichess 所有模式是否都能免注册，因此不将此写成比较事实。

2. Board Game Arena：先让人做一手，信息按当下任务展开

官方证据。 官方教程公告将教程置于游戏的玩法介绍中。官方教程建设页（搜索索引可读，直接访问超时）要求先说明主题和目标、尽快展示行动、必要时再解释规则，并让学习者亲自操作。官方 UX 指南 PDF第 3–4 页讲局面与当前行动，第 15 页讲日志，第 19–20 页讲结局与刷新恢复。PDF 的版本页注明 2025-10-10 v1.0.0，是平台指导而非所有游戏都已遵循的证明。

用于我们。 先做一轮可跳过的确定性样例，依次操作“行动 / 人群 / 投入”，看到费用，再确认，最后读一条结果解释。不要先让用户阅读综合分公式和结算顺序。正式倒计时内使用不挡操作的简短提示；等待同学期间或独立练习中才做完整引导。

行动区结构。 常驻状态写“第 1/6 轮 · 请选择本轮行动”，保留一个主确认动作；旁边显示提交状态和截止前可修改。其他人的详情、历史记录与稀有术语按需展开。酒馆圆桌负责共同在场感，资源与提交控制保持清楚，不将所有信息压到 3D 桌面。

边界。 BGA 的蓝色确认、红色取消属于其自身的平台语言，不宜覆盖我们的朱红主色。借鉴“意义一致”的原则即可。它的社区教程制作和公开匹配系统也不适合第一阶段直接搬来。增长酒馆已有提交反馈和恢复能力，本项重点是新手如何读懂，不是重新实现网络层。

3. Brilliant：问题、操作、反馈、引导串成同一学习单位

官方证据。 当前官网已经以 Koji 可视化辅导为主，描述共享互动画布和引导式提问；当前官方 FAQ说明通过互动问题、视觉模型和即时反馈学习，辅导围绕当前题目逐步提示。没有使用记忆中的旧版关卡截图作为 2026 年的界面证据，也不引用其营销效果倍数。

用于我们。 当前实验室中“调滑块看结果”的模块可增加一个短预测：“新增不变，如果留存率下降，你预计第 6 轮人数会怎样？”用户先选判断，再操作，再获得基于当前模型的解释。酒馆主持也可优先提出一个由公开事实支持的问题，例如“本轮新增增加了，为什么有效用户仍可能减少？”点击“看解释”再展开两句说明。

落地状态。 未作答时仅有一个问题；提交后显示“你的预测”和“模型结果”；允许“重新试一次”，保留返回刚才回合的锚点。回答不按经营胜负简单判对错，数学实验可在已声明的模型下评价预测。

边界。 当前原生产品是一套辅导体系，不能据官网宣传推断它所有课程都具备相同互动。我们也不需要先做全天候聊天助手、学习画像或新模型服务。先用现有实验模型和规则模板完成闭环，避免把课堂开局变成一串问卷或 AI 对话。

4. Duolingo：给出一个可信的下一步，保留跳过新手教学

官方证据。 当前官方加课说明展示选择课程、选择水平、从头或测级后进入第一课。2022 年首页路径改版说明解释把内容和复习组织在建议路径中，降低“不知道接下来做什么”的负担。后者明确是历史设计动机，不能用来断言今日每个课程的全部布局。

用于我们。 不是把六轮经营变成锁死关卡，而是在关键状态只推荐一项下一步：未加入时“加入课堂”，已入席时“等同学到齐 / 看一个操作样例”，开局时“选择本轮行动”，结束时“复盘一处决策”。熟悉产品的人可以直接进入正式局或继续原房间；新手帮助可跳过。

示例结构。 主页第一屏用一句话解释“和三位同学各自经营公司，共享同一市场，用六轮决策验证增长判断”，下面一个酒馆主入口。进入后根据邀请和现有会话决定下一步。阅读地图仍可自由探索，不为了导航的整齐而强迫先读六章。

边界。 不照搬 streak、生命值、排行榜压力和多页目标问卷。课堂目标是同学同步完成首局与解释判断；长期留存机制应等基础体验被验证后再考虑。

5. Readwise Reader：解释和札记留在原文、原决策的上下文里

官方证据。 Reader 产品页展示阅读与标注的结合。官方高亮/标签/札记文档说明宽屏旁注、段落级键盘导航、对选文添加注释，以及从高亮返回原文位置。这是官方描述，未在登录产品中实测。

用于我们。 酒馆复盘中的术语可以在原决策旁展开简洁概念卡，再选择“读完整一篇”。笔记保存真实来源：房间、轮次、行动、公开结果与用户解释；再次打开札记时可以回到那处回合或原文段落。已有文末“写一点思考”与结束后的“写进我的札记”是基础，应增强来源和返回路径。

示例文案。 “留存：本轮留下的老用户占上一轮用户的比例。看看这次行动与留存变化有什么关系。”其下为“读相关段落”和“回到第 3 轮”。移动端用简洁底部卡片或原位展开，关闭后回到原滚动位置。

边界。 不搬全套 RSS、全文库、文件导入和复杂键盘体系。桌面专业阅读器的侧栏数量也不适合课堂手机首屏。概念弹层应按需触发，不能在每个新术语出现时自动打断操作。

三条最值得先打通的路径

路径 A：从课堂邀请到第一轮有效行动

  1. 扫到组长分享的桌链接，系统识别已有 room，显示“加入这桌”和桌名/代码；保留现有仅填称呼的低门槛。
  2. 如果同学只拿到代码，无邀请页优先提供“输入课堂代码加入”，而不是默认建新桌。入口有错码、已满、已开始且不能加入、网络待确认等明确恢复动作；同一设备已有有效会话则优先“回到原席位”。
  3. 到桌后显示“你在第 X 席，已到 X/4 人，等组长开始”。组长和普通玩家看见各自可做的事；不能把所有人都导向“开始经营”。
  4. 等待阶段可点一个不计入正式成绩的操作样例；正式第一轮显示一条行内提示与主确认按钮。无需连接 Agent 也能完成行动，Agent 为可选帮助。

参考组合：Lichess 的按意图入口 + Duolingo 的状态化下一步 + BGA 的动手式教程。验收用真实四人桌，而不是四个静态页面：1 名组长开桌、2 名同学用邀请加入、1 名用代码加入，各自能说明自己在哪桌、等谁、谁能开局，并完成第一次合法提交。

路径 B：从一个不懂的变量到一个能解释的决定

  1. 行动或账本旁的概念入口保留当前轮次，不离开房间就能读两句解释。
  2. 愿意进一步理解时打开对应实验，先做预测，再操作一个变量，观察确定性模型反馈。
  3. 用一句话写下假设，返回原房间与原页签；如果正式局仍在倒计时，只提供简短解释，不诱导离开去做长实验。

参考组合：Brilliant 的问题—操作—反馈 + Reader 的上下文阅读。验收不是“所有链接都能点开”，而是新同学能据结果解释留存和新增为何共同影响有效用户；明确知道实验是教学模型，不是对本局胜负的保证。

路径 C：从一局结束到一条可讨论的学习产出

  1. 结果页先展示实际成绩、排名和分数构成的可读说明，再给出一处值得复盘的真实轮次。
  2. 点入后看当时公开信息、自己的实际行动及结算变化；先让用户解释，必要时再展开主持解读。
  3. 将“事实 / 我的解释 / 下次要验证的假设”写入现有札记，附回到该回合和相关概念的入口。
  4. 课堂分享可显示匿名或经用户选择的简要学习卡；不默认公开私人决策、Agent 对话或凭据。

参考组合：Lichess 的局面定位复盘 + BGA 的结局与日志 + Reader 的来源记录。第一阶段不必做反事实经营引擎；可以先把已有事实、回合日志和札记串起来。

可直接转成计划的八项映射

编号 / 优先级屏幕与当前可见基础具体改进与参考部位验收要点
R1 / P0酒馆大厅已有新开/加入页签；邀请自动切加入按上下文选择默认任务；无邀请课堂页突出输入代码，组织者开桌独立命名。参考 Lichess 首页三个意图按钮学生不会误建自己的桌；邀请加入仍只填称呼；原席位优先恢复
R2 / P0等待页已有 4 席状态和组长开局增加“你是谁、现在等谁、接下来做什么”一句状态；区分组长/参加者。参考 Duolingo 下一步与 BGA Action bar四人能各自说出当前状态和下一步；无权限按钮不造成困惑
R3 / P0行动表单已展示行动/人群/投入与费用等待时提供可跳过的样例教学，正式局用不阻挡的行内帮助。参考 BGA 教程“让用户自己走一手”首次合法提交无需口头逐字段指导；不会消耗正式倒计时强迫读教程
R4 / P0提交已有接收、失败与不确定状态用教学文案解释“已收到但可在截止前改；已锁定不能改”；保留草稿与重试。参考 BGA 当前行动与失败原因用户能区分草稿/已接收/已锁定；掉线后知道是否要重试，避免重复误操作
R5 / P1结果已有分数/排名、札记、导出增加分数构成与按实际轮次定位的“本局转折”；不称负结果为确定错误。参考 Lichess 5.5 与 BGA Endgame用户能解释至少一处结果；每条结论可追溯公开事实；不靠下载 JSON 才能复盘
R6 / P1实验已有变量操作和模型结果加一个可跳过的短预测与针对结果的两句解释。参考 Brilliant 当前互动问题与即时反馈用户先后判断可比较；说明模型适用边界；不延长课堂主开局路径
R7 / P1阅读有札记入口；游戏可保存复盘札记附来源锚点与回到原回合/段落；概念原位展开。参考 Reader 旁注与返回来源离开和返回保留位置；笔记能说明从哪次行动而来；手机不需多栏
R8 / P1真实圆桌、经营信息、行动区已存在圆桌负责共同在场；经营信息按任务分组；桌面固定任务层级，手机把主要行动置前，细节按需展开。参考 BGA PDF 第 3、13、18 页100% 手机缩放能读完并提交；无需拖 3D 场景找控件；座位身份不用只靠颜色

P0 表示首局成功必须优先解决的体验问题，不代表已证实每名学生都失败。P1 表示首局可用后提高理解与复盘价值。建议先测现状再定量，不把外部产品的商业转化率直接当我们的目标。

课堂真实用户测试建议

建议招募 8 名从未使用过产品的同学，分成两桌；这是小规模可用性试验，不代表统计显著性。第一桌先测当前版，第二桌测可点原型；后续交换时记录学习效应，不直接将交换后的速度当独立样本。至少包含普通手机与较弱网络；桌面窄视口只能作为布局检查。

依次给出三项任务：加入指定桌并说出下一步；完成第一轮并解释是否已提交；结束后找一轮说明“我当时根据什么做决定”。观察者先不解释术语，只有卡住时帮助并计为需要协助。记录错建桌次数、加入耗时、首轮合法提交耗时、求助位置、对“接收/锁定”的复述、能否把结果与证据对应。另测邀请已满/错码、刷新回席、临时离线；异常测试用受控环境。

建议验收门槛是设计目标而非当前已达成绩：8 人中至少 7 人无需口头帮助加入正确桌，0 人因首页分流误建桌；至少 7 人能正确区分已接收与截止锁定；至少 6 人能提出包含真实回合证据的复盘解释。若未通过，先修触发卡点，不新增排行榜、成就系统或更复杂的 AI 层。

判断

最有价值的借鉴组合是：Lichess 的意图入口与局后分析、BGA 的可操作教程与当前行动状态、Brilliant 的即时因果反馈、Reader 的上下文笔记、Duolingo 的明确下一步。应仿照这些局部机制，把“进入一桌 → 做一个决定 → 理解一次结果”做完整，而不是把五个产品的外观拼到同一页面。
