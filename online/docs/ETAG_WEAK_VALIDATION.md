# 公网条件轮询修复

版本6的两桌六轮报告中，1016次普通轮询均返回200，没有304。真实公网探针收到 `W/"…"`：原样回传得到200，去掉 `W/` 后得到304且正文0字节。服务端原先只做强标签字符串全等，未正确处理平台返回的弱标签。

`If-None-Match` 必须按弱比较处理，比较区分大小写的opaque值，支持列表与独立通配符；这是 [RFC 9110 §13.1.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2) 和 [§8.8.3.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.3.2) 的规则。鉴权、资源存在性和到期状态推进仍先执行。

`worker/room-transport.js` 的 `etagMatches()` 使用引号感知解析，Node与Worker共用。独立10项测试覆盖弱标签、列表、通配符、引号内逗号、大小写、无效语法、鉴权和截止推进。

旧六轮数据保持原样：48次accepted的p95为2473.95毫秒，未达到候选2000毫秒目标；13/14条DeepSeek与1条真实模板回退。修复后的公网304、流量与延迟必须另测，不能把本地10项通过当作公网性能改善。
