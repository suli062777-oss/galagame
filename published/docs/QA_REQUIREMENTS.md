# V3 独立验收范围

验收按《酒馆体验改进计划》及用户新增的模型细节、酒馆背景氛围要求进行。既有 API/模型业务检查不等于新增界面通过。

| 范围 | 需要的证据 | 不能替代它的证据 |
|---|---|---|
| 四人同桌及六轮 | 四个独立 HTTP 凭据、六轮动作与共享账本、回放、头像保留 | 单人静态画板、脚本人物截图 |
| 桌面信息架构 | 1440×900、1280×800 实际浏览器；经营摘要、三个信息页签、单个主操作可见可用 | 选择器存在、CSS 文本扫描 |
| 手机 | 390×844、360×800 实际浏览器；底部入口、可关闭动作/信息面板、计时可见，无横向溢出 | 仅把桌面缩小的截图 |
| 操作状态 | 真正 DOM 提交；草稿保留、服务器回执、失败提示、锁定不可提交 | 仅 API 200、成功提示字符串 |
| Three | 实际 WebGL + 独立帧截图；四席归属、头像锚点、桌球间距、缩放上限、窗口改变、低性能模式 | PNG 代替场景、仅默认几何尺寸 |
| 氛围 | 浏览器截图看得到暖木/黄铜材质、灯光和酒馆背景细节，正文及 CTA 层级仍清楚 | 代码里存在“bar”“lamp”等命名 |
| 真实性 | 模板/真实主持据实标记，角色权限及 12 次预算不变，本轮 QA 不触发生产模型 | enabled 配置、假 provider |

执行工具：

- Node v24.13.1，可用原生 HTTP、SQLite、现有离线测试。
- `scripts/qa-v3-api.mjs`：独立进程创建本地 HTTP 服务，以可控服务时钟完成四端六轮、头像与 Worker 引擎一致性证据。
- `scripts/qa-v3-browser.mjs`：由用户打开 `/?qa=1` 后在该真实浏览器内执行实际 DOM 操作，报告 POST 到同源 `/__qa/report`。只允许 localhost，不请求生产，不保存凭据。
- 当前没有显式官方 Browser/CUA 工具；Node_REPL 中 browser/cua 未初始化。历史浏览器启动被策略拦截，本轮不更换启动方法绕过。

尚待实际浏览器执行的项目必须保留为未验证。浏览器内 QA 不证明设备外的其他视口通过；每个视口需单独运行并保存报告和截图。首次新用户 15 秒观察目标及真实设备 FPS 需实际观察测量，不以实现者判断代替。

报告区分如下：

- `progress`、`completed`、`failed` 保存每项实际耗时、页面可见状态、当前回合及最近 50 条脱敏 API 事件；路由中的房间标识替换为 `[test-room]`，不保存请求头、凭据或动作请求正文。
- `scene-snapshot` 单独保存本项目 WebGL 场景的实际 PNG，不含控制栏或页面文字；它用于独立检查材质/模型/市场可见性，不能证明整个页面布局。
- Figma 官方脚本的返回或本地等待超时不代表捕获成功；需以原生采集状态确认。已消费的采集 ID 从通用 QA 脚本移除。
- 捕获期间的参考房间与完整六轮测试房间分开：采集后新建真实练习房，保留服务器的真实阶段时限。
- 脚本对练习模式的三个席位始终按脚本角色报告；四个真人凭据的并发属于独立 HTTP 测试证据，不称为四人真人浏览器游玩。
- 初始分数全为 0 时中性市场是正确语义；球体过暗、图形不可读仍是视觉问题。几何包围及零运行错误不能替代这一审美检查。
